# 桌面版

从「浏览器里的一个网页」变成「随时待在你屏幕边上的助手」。

> 这份文档替代原来 `SCREEN.md` 里的产品形态假设。看屏幕的功能设计还有效，
> 但「怎么呈现、怎么唤起、怎么和别的应用共存」全部重做。

---

## 一、为什么必须换架构

需求确认了六条，其中三条**网页根本做不到**：

| 需求 | 网页能做到吗 |
| --- | --- |
| 浮在所有窗口最上面，一直看得见 | ❌ 浏览器窗口没法置顶在别的应用之上 |
| 全局快捷键唤起 | ❌ 网页只能在页面有焦点时收键盘 |
| 截屏时不被自己挡住 | ⚠️ 能做但很别扭（网页没法最小化自己） |
| 看屏幕上框住的那一块 | ✅ 已经在做了 |
| 语音对话 | ✅ 已经在做了 |
| 经同意后替你操作 | ⚠️ 网页不能模拟鼠标键盘 |

前三条是硬伤。所以：**包一层桌面外壳**。

好消息是——对话、工具调用、语音、记忆、人格，这些**一行都不用重写**，
它们本来就是跑在本机的 Next.js 进程里。Electron 只是给它加一个「能置顶、能收全局快捷键、
能隐藏自己」的窗口。

---

## 二、目标形态

```
┌──────────────────────────────────────────┐
│  别的应用（Excel / 浏览器 / 你正在用的）    │
│                                          │
│         ┌────────────────────┐           │
│         │  frame             │  ← 悬浮小窗
│         │  点右上角那个齿轮，  │     置顶、无边框、
│         │  把「共享」改成「仅  │     可拖动、半透明
│         │  自己」就行         │
│         └────────────────────┘           │
│                                          │
└──────────────────────────────────────────┘
```

- **平时**：小窗缩成一条，只显示状态点（在听 / 在想 / 在看）
- **说话时**：文字在窗里滚出来，同时有语音
- **需要完整界面时**：点小窗展开成大窗（就是现在的界面）

## 三、技术方案

### 外壳：Electron

| 为什么选它 | |
| --- | --- |
| 复用现有代码 | 窗口直接加载现有的 Next.js 服务，界面和逻辑都不用改 |
| 置顶窗口 | `BrowserWindow({ alwaysOnTop: true, frame: false, transparent: true })` |
| 全局快捷键 | `globalShortcut.register()`，跨应用生效 |
| 截屏 | `desktopCapturer.getSources()`，比现在调系统命令干净 |
| 隐藏自己再截图 | `mainWindow.hide()` → 截 → `show()`，一次解决「只能看到自己」 |

不用 Tauri 的原因：Rust 那套要重写一部分窗口逻辑，而且它的 WebView 在 Windows 上
用的是 WebView2，和 Chrome 的语音 API 兼容性要多验一轮。Electron 直接就是 Chromium，
现有的 Web Speech API、MediaRecorder 全部原样能用。

代价是安装包大（100MB+）。用户已经确认接受。

### 三个进程 / 窗口

```
Electron 主进程
├─ 主窗口       现在的完整界面（对话、设置、记忆）
├─ 悬浮窗       独立小窗口，置顶，只显示当前这句
└─ Next.js 服务  跟着主进程一起起来，跑 /api/*
```

悬浮窗不重复实现逻辑，它订阅主进程转发过来的「当前要说的话」。

### 截屏流程（修掉「只能看到自己」）

```
按快捷键 / 点悬浮窗的「看这块」
        ↓
主窗口 hide()          ← 关键：先把挡路的藏起来
        ↓
等 200ms（等窗口动画结束）
        ↓
desktopCapturer 截全屏
        ↓
主窗口 show()          ← 框选界面铺开
        ↓
拖框 → 确认 → 开始看
```

之后每次说话时截图，主窗口本来就在后台，不会挡住。

### 动作层（替你操作）

用 PowerShell 的 `SendInput`，不引原生模块。

理由：`robotjs` 这类包每次 Electron 升级都要重新编译，对非开发者是灾难。
系统命令慢一点（每次 100ms 左右），但零编译、零依赖。

**六道防线照旧**（`SCREEN.md` 第六节），一条不省：
坐标锁框内、动作前高亮、一次一个动作、危险词强制弹窗、随时可打断、操作留痕。

## 四、分期

| 阶段 | 做什么 | 做完能干什么 |
| --- | --- | --- |
| **D1** | Electron 外壳，把现有界面跑起来 | 双击图标启动，界面和现在一样 |
| **D2** | 悬浮窗（置顶、可拖、可折叠）+ 全局快捷键 | 切到任何应用都能看到它说话，按快捷键唤起 |
| **D3** | 截屏换成 `desktopCapturer`，修「只能看到自己」 | 真的能框到任何窗口 |
| **D4** | 动作层 + 六道防线 | 经你同意后，替你点按钮、打字 |
| **D5** | 打包成安装包（exe） | 双击安装，像正常软件 |

D1 和 D2 是地基，必须连在一起做——只有外壳没有悬浮窗，等于什么都没变。
D3 是个独立 bug 修复，随时可插。D4 风险最高，放最后。

---

## 五、风险

| 风险 | 应对 |
| --- | --- |
| Electron 打包后 Next.js 的 API 路由可能跑不起来 | D1 就先验这一条，跑不通立刻换方案（静态导出 + 客户端直连） |
| 悬浮窗抢焦点，导致你在别的软件里打字打一半被切走 | 窗口设 `focusable: false`，只显示不抢焦点 |
| 全局快捷键和别的软件冲突 | 默认 `Ctrl+Shift+Space`，设置里可改 |
| 100MB+ 安装包 | 已确认接受 |
| 动作层误操作 | 六道防线 + 默认关闭 + 首次使用强制走一遍演练 |

---

## 六、不做什么

- **不砍网页版**。开源项目里网页版留着，别人 `npm run dev` 就能用；
  Electron 只是多一个入口。两套共用同一份源码。
- **不做常驻后台截屏**。没框选的时候一次都不截。
- **不做「它自己看出你卡住了主动开口」**。你确认过要按键唤起，
  而且主动开口这件事误判率高，不做。
